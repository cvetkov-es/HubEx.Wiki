## Доступ к заявкам, альтернативные каналы и групповые действия

Кто какие заявки видит и какие поля правит, каналы подачи заявок помимо приложений, действия над списком заявок сразу.

**Модель.** Видимость заявок задаётся двумя слоями: полномочия «Роли» (блок «Заявки» → «Справочники») и настройка полей формы в разрезе «Роль» × «Стадия заявки». Варианты полномочий: «Активные заявки на сотрудниках моих участков», «Активные заявки на объектах моей компании», «Активные заявки на сотрудниках моей компании», «Все активные заявки», «Активные заявки по моим видам работ», «Дочерние активные заявки», «Заявки, на которые я когда-либо был назначен» (даже если исполнителя заменили), «Заявки, где пользователь — ответственный за объект по заявке», «Заявки на объектах, доступных пользователю» (следует из блока «Объекты» → «Справочники»), «Удалять незакрытые заявки», «Предоставляет доступ на чтение и запись для всех компонентов формы заявки вне зависимости от полномочий и настроек стадии» (снимает ограничения полей формы). Видимость «Объектов»: «Все активные объекты», «Удаленные объекты», «Объекты на участках пользователя», «Объекты у компаний пользователя» (совпадение «Компании-владельца» объекта с компанией сотрудника из вкладки «Трудоустройство» / заказчика из вкладки «Общее»). Уровни доступа к полю: RO (только чтение), RW (чтение и запись, редактирование необязательное), RWM (чтение и обязательная запись), «Настройка не выбрана» — поля нет на форме. «Инициатор заявки» — поле с данными о пользователе, создавшем заявку (при звонке инициатором становится диспетчер); по каждому инициатору хранится история обращений — список заявок с ним, открывается из контекстного меню у ФИО. Список выбора инициатора формируется из всех «Заказчиков» и «Сотрудников» аккаунта. Каналы подачи: паспорт объекта по QR (поле «Метод подачи заявки» = «Паспорт объекта»), электронная почта (пересылка либо imap), форма на сайте компании-исполнителя. Почтовая интеграция опирается на шаблон заявки из «Заявки — Маркировка» и сервисную учётную запись. Двусторонняя интеграция: сообщения из вкладки «Сообщения» уходят ответным письмом на адрес отправителя заявки. Участки, роли, приглашения — [s09], [s11]; шаблоны и QR — [s07]; клиентский портал и приложение заказчика — [s24].

**Настройка.** Поля формы: `Консоль администрирования → Настройки заявки → Поля на форме заявки` (дополнительные поля — внизу таблицы с отметкой «А»; создаются в `Настройки системы → Дополнительные поля`). Копирование настроек — контекстное меню (три точки) у «Роли» или «Стадии» → «Копировать в…». Полномочия: `Консоль администрирования → Администрирование → Роли → вкладка «Полномочия»`. Почта: `Консоль администрирования → Интеграция → Интеграция по электронной почте` (разделы «Подключение через пересылку» и кнопка «Подключить эл. почту»); сервисный пользователь — `Интеграция → Служебные пользователи`, тумблер «Пользователя API», выбрать «Роль» с максимальными полномочиями по заявкам и объектам и «Участки» (рекомендуется все); «Токен доступа» для почты не нужен. Поля подключения imap: «Адрес сбора заявок», «Логин», «Пароль/Ключ» (пароль приложений почтового сервиса), «Хост», «Порт», «Сетевой протокол», «Протокол безопасности»; для Yandex — imap.yandex.ru, 993, SSL/TLS. «Отправитель» — конкретный адрес, `*@yandex.ru` или `*@*`; для общего шаблона без заказчика указывать `*@*`. Переключатели «Разрешить получение писем», «Возможность ответа заказчику через чат», общий тумблер включения интеграции. «Настройка регулярных выражений» — парсинг письма в поля заявки («Объект», «Вид работ», «Срок закрытия» и т.д.), подключается через help@hubex.ru; форма подачи на сайте — тоже через help@hubex.ru. Шаблон для пересылки создаётся по умолчанию с названием «Шаблон для получения заявок по электронной почте через пересылку», публиковать его для этой интеграции необязательно, флажок «Разрешить подачу заявки из Web» установлен по умолчанию, снимать не нужно. Массовые действия: `Заявки → Все заявки`, навести курсор слева от заявки, флажок → верхняя панель → «Редактировать» → «+ Изменить» (исполнители) → «Выбрать» → «Применить», либо «Удалить» с подтверждением. Удалённые заявки ищутся фильтром «Видимость заявок» = «Только удаленные».

**Ограничения.** Массовые действия доступны для карточного и табличного представления списка; заполняют/заменяют «Исполнителя» и удаляют заявки. Флажок в панели редактирования выбирает все заявки на странице. Нельзя отключать видимость поля «Тип заявки»; хотя бы для одной «Роли» и «Стадии» ему должна быть назначена RW. Остальные поля не обязательны, их можно исключить из формы. У шаблона для imap-интеграции обязательно должны быть выбраны «Объект» и «Вид работ», иначе шаблон не выбрать в настройках интеграции. imap-интеграцию нельзя настроить для outlook.com и mail.ru; рекомендуются адреса yandex.ru, другие сервисы могут работать нестабильно. Если письмо на адресе сбора заявок прочитать в почте, заявка в HubEx не создастся. Все действия над полем «Инициатор заявки» доступны только ролям, которым выдано редактирование этого поля. При создании инициатора обязательны ФИО и одно из полей «Телефон»/«Электронная почта».

**⚠ Грабли.** Пустая форма заявки (белый экран) — следствие того, что для новой «Стадии заявки» не задано ни одной настройки доступа к полям. Сотрудник должен принадлежать тому же «Участку», что и исполнители, которых он назначает, иначе их нет в списке выбора. Если у сотрудника/заказчика есть «Участок», а в «Типе заявки» участок не выбран, тип недоступен и заявку создать нельзя. Пустой список заявок часто вызван активными фильтрами (красная точка на кнопке фильтров в мобильном приложении). При изменении «Заказчика» в заявке после выбора инициатора поле «Компания» у инициатора не изменится. По умолчанию новые «Инициаторы заявки» создаются как элементы справочника «Заказчики». В шаблоне для пересылки по умолчанию «Тип заявки» — созданный в системе первым, «Вид работ» — с флажком «Основной вид работ» (он один в системе), «Критичность» — с флажком «По умолчанию»; текст письма заполняет «Описание заявки». Ссылка-подтверждение пересылки от Gmail/Yandex приходит на почтовый ящик HubEx и превращается в заявку — её нужно искать в «Описании заявки». «Приглашение» для почтовой интеграции указывать не нужно. Для каждого нового адреса клиента создаётся карточка «Заказчика», ему уходит письмо со ссылкой для регистрации.
