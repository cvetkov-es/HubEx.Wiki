## SLA, автоназначение и чек-листы

Три механизма автоматизации заявки: расчёт «Крайнего срока закрытия» (SLA), подбор исполнителя роботом-диспетчером и чек-листы работ. Связующий справочник всех трёх — «Вид работ».

**Модель.** Вид работ — специфический вид деятельности (услуг), который может выполняться Сотрудником и направлен на Объект; классифицирует Объекты, Сотрудников и Заявки. Поля: «Название вида работ», «Описание», «Чек-лист выполняемых работ» (автоматически подтягивается в Заявку при выборе вида работ), «Плановые трудозатраты» (для автоматического расчёта срока окончания работ на форме выбора исполнителя), «Время закрытия заявки», «Основной вид работ» (подставляется по умолчанию при создании нового Объекта), «Опубликован» (тогда доступен для указания у Объекта, Сотрудника и выбора в Заявке), «Стоимость вида работ» (формирует итоговую сумму по Заявке в Акте выполненных работ [s13]; автозаполняется при создании выполненных работ на вкладке «Выполнение», можно изменить вручную).
Источники крайнего срока: Тип заявки, Вид работ, правило SLA. Из значений Типа заявки и Вида работ система выбирает наименьшее [s02].
Правило SLA сопоставляет параметры Заявки и при совпадении заполняет «Крайний срок закрытия»; применённое правило показывается на форме Заявки внизу в поле «Правило расчета крайнего срока закрытия». Срок = «Плановое время закрытия заявки» (максимальный срок выполнения работ), отсчитанное по «Графику обслуживания» (рабочее время выполнения Заявок). Пример: обслуживание по будням 9:00–18:00, заявка подана в чт 17:00, плановое время 6 ч → крайний срок пт 14:00.
Правило автоназначения — набор критериев: «Обязательные навыки» (совпадение обязательных навыков карточки объекта из заявки с карточками сотрудников), «Вид работ» (самый популярный параметр), «График работы» (у кого рабочая смена на момент подачи заявки [s11]), «Ответственный за объект» (указывается в карточке объекта на вкладке «Обслуживание»), «Часто назначается на объект», «Участок» (участки карточки объекта против вкладки сотрудника «Квалификация» [s09]). Правило действует только как действие Стадии заявки [s01].
Чек-лист = Пункты; Пункт может содержать Атрибут — способ измерения/выражения (число, дата, текстовая строка, вложенный файл). Без атрибутов пункт отмечается флажком. Привязка чек-листа к Объектам/оборудованию и (или) Видам работ даёт автоприкрепление к Заявке при выборе их в Заявке; без привязок — добавление вручную. Чек-листы заявки видны на вкладке «Чек-листы».

**Настройка.** Путь: Консоль администратора → Настройки заявки → «SLA: расчет крайнего срока закрытия» → «Создать правило» (разрезы: Тип заявки, Критичность, Вид работ, Компания-заказчик, Объект; Заказчики «Все»/«По списку», Объекты «Все»/«По списку»/«Все за исключением»; «Все» включает и будущие записи). Правило нужно включить переключателем («Включено») — при создании или позже в общем списке.
Путь: Консоль администратора → Настройки заявки → «Виды работ» → «Создать вид работ». Также создаётся из формы Заявки (кнопка «+»/«Создать +») и из Объекта, вкладка «Обслуживание» → «Добавить» → «+ Добавить».
Путь: Консоль администратора → Настройки заявки → «Автоназначение исполнителя» → «Создать правило»; либо на форме создания/редактирования Стадии заявки кнопкой «+» после выбора действия. Переключатель «Детальная настройка» задаёт степень важности параметров в процентах.
Путь: Консоль администратора → Настройки заявки → «Стадии заявки» → стадия → поле «Действие» = «Автоназначение по правилу» или «Автоназначение с учетом удаленности от заявки» → выбрать правило. Появляется параметр «Роль». Автопереход на стадию: Жизненный цикл заявки → переход → «Выполнить автоматический переход» + время [s01].
Путь: Чек-листы (левое боковое меню HubEx) → «Создать чек-лист»: «Название чек-листа», «Описание», «Объекты», «Виды работ». Атрибут: Консоль администратора → Настройки системы → «Дополнительные поля» → «Создать новое поле» → «Наименование поля», «Тип поля» (напр. «Вложенный файл»), «Используется для» = «Чек-листы» [s16]. Блокировки: Стадии заявки → требование «Обработаны чек-листы»; Поля на форме заявки → «RW» для поля «Чек-листы».

**Ограничения.** Правило SLA создаётся только на один Тип заявки, одну Критичность и один Вид работ, либо значение «Все» по каждому пункту. Выбор Объектов доступен только после выбора Заказчика(ов). Графики обслуживания и графики работ встроены в систему; уникальный график добавляет поддержка (Чат с поддержкой в web-приложении или help@hubex.ru). Конфликт правил SLA: работает то, которое по Графику обслуживания попадает на текущее время; при совпадении Графиков обслуживания — правило с наименьшим сроком закрытия. Для участия в автораспределении в карточке Сотрудника должен быть установлен флажок «Мобильный сотрудник». Чтобы выбрать Вид работ в Заявке по Объекту, Виды работ должны быть указаны в карточке этого Объекта и добавлены к Типу заявки. Вложенным файлом может быть фото или видео; в WEB-версии в чек-лист можно приложить .doc, .xls, .pdf; допускается несколько файлов к одному пункту.

**⚠ Грабли.** Установленный вручную «Крайний срок закрытия» правилом не изменяется. Новый Вид работ НЕ добавляется автоматически в уже созданные Объекты и НЕ привязывается к карточкам существующих сотрудников — привязка вручную; через карточку сотрудника создать новый вид работ нельзя, только добавить ранее созданный. Автоназначение: с выключенной «Детальной настройкой» выбранные параметры применяются с союзом «И», с включённой — с союзом «ИЛИ», в зависимости от выставленного процента. Переход на стадию с правилом может быть ручным или автоматическим — при ручном переходе подбор Сотрудника тоже выполняется автоматически. При создании новой Стадии заявки нужно изменить настройку Жизненного цикла заявки, если он уже создан и настроен. Вручную добавлять и удалять чек-листы в заявке можно только через WEB-версию, в мобильном приложении такой возможности нет; офлайн чек-лист заполняется и сохраняется, получает значок синхронизации и загружается автоматически при появлении сети. Карта расстояния до Объекта открывается в Заявке: «Исполнитель» → «Показать исполнителей на карте» [s20].
