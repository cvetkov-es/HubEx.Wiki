## Аналитика Power BI

Семейство аналитических панелей HubEx на платформе Power BI. Меню **Аналитика**: «Общая аналитика», «Отчет по сотрудникам», «Отчет по объектам обслуживания», «Отчет для клиента», «Анализ эффективности процессов». Данные во всех отчётах обновляются один раз в сутки, дата обновления показана на панели. Плоские выгрузки — s19.

**Модель.** Все панели строятся на данных «Заявок»: «Общая аналитика» — по заявкам, «Отчет по сотрудникам» — заявки в разрезе сотрудников, «Отчет по объектам обслуживания» — в разрезе объектов, «Отчет для клиента» — в разрезе заказчиков, «Анализ эффективности процессов» — по маршрутам стадий. Расчёты зависят от заполнения вкладки «Выполнение» в заявке (время работ), графиков работы в карточке «Сотрудника», рейтинга заявки, «Крайнего срока закрытия». Просроченная заявка — закрытая позже крайнего срока.
Процесс = последовательность прохождения заявки по конкретному набору стадий; разные наборы («Новая — Назначена — В работе — Выполнена — Закрыта» против маршрута с «Не принята исполнителем») — разные процессы. Цикл — прохождение через одну/несколько одинаковых стадий более одного раза.
«Коэффициент полезной загрузки исполнителей» (Utilization Rate) = длительность всех выполненных работ за период / часы по графикам работ. «Количество выполненных заявок на исполнителя» = выполненные заявки за период / среднедневное количество исполнителей по графику. «HubEx Рейтинг» считается по четырём показателям: количество закрытых заявок за период, % закрытых с нарушением SLA, количество выполненных работ (часов), рейтинг от заказчиков; значение 1 — самый эффективный за период. MTBF — среднее число часов между возникновением заявок; MTTR — среднее время выполнения работ на объекте. «Отработано всего» учитывает пересечение времени (три работы 12:00–13:00 = 1 час), «Выполнено работ» — без учёта пересечения (те же = 3 часа). «Переработки» — часы из «Выполнения», не входящие в График работы. Активный объект — объект, по которому за последние 4 недели создана хотя бы одна заявка; аналогично активный родительский объект. «SLA подрядных организаций» = закрытые с просрочкой / все закрытые за предыдущий месяц.
Разбиение исполнителей на 4 квадранта в «Сравнение эффективности исполнителей» по осям «Среднее кол-во выполненных заявок в день» и «Закрыто в срок, %» относительно средних по организации: 1-я (верх-право) — оба выше среднего; 2-я (верх-лево) — мало заявок, без нарушений SLA; 3-я (низ-лево) — мало заявок и нарушения SLA; 4-я (низ-право) — много заявок с просрочкой, перегружены. Заявки с 4-й категории можно переназначать на 2-ю.

**Настройка.** Путь: Аналитика → Общая аналитика / Отчет по сотрудникам / Отчет по объектам обслуживания / Отчет для клиента / Анализ эффективности процессов. Период — слева вверху. Кнопка «Фильтров» / «Открыть панель фильтров» (справа): «Тип заявки», «Участок», «Должность», «Вид работ» и т.д.; фильтр применяется ко всем визуализациям панели (в «Отчете по сотрудникам» — на всех вкладках). В «Анализе эффективности процессов» для «Варианта А» и «Варианта В» доступны свои наборы фильтров.
Вкладки «Отчета по сотрудникам»: «Заявки и SLA», «Отработанное время», «Показатели и KPI»; плюс отчёт-карточка сотрудника — щелчок по ФИО в любой визуализации и кнопка-стрелка на панели настроек. Вкладки «Анализа эффективности»: «Выявление проблем в бизнес-процессах», «Сравнение эффективности бизнес-процессов», «Время прохождения заявок по стадиям» (поля «Со стадии 1» и «На стадию 2»).
Детализация: кнопки «Открыть аналитические разрезы» / «Включить аналитические разрезы», добавление разреза по «+», сброс — крестик у характеристики. Детализация по дням/неделям/месяцам — кнопки ↑ / ↓↓ при наведении на визуализацию. «Режим фокусировки» — разворот визуализации. Выбор показателя визуализации — «Открыть меню визуализации» / «Открыть параметры визуализации» (синяя шестерёнка). Экспорт в Excel: контекстное меню (три точки) → «Экспортировать данные». В «Отчете по объектам обслуживания»: переключение таблицы показателей с плоской структуры на иерархическую, переход по кнопке «В отчет по объекту», возврат кнопкой «Назад» (синяя стрелка). Флажки «Мобильный сотрудник» и «Отслеживать местоположение сотрудника», «Должность» — в карточке «Сотрудника» (s09, s11); геотрекинг — s20.

**Ограничения.** «Количество переходов по стадиям» — по умолчанию ограничение отображения до 30 000 переходов; расширение — через чат с поддержкой в web-приложении или help@hubex.ru. Период активности объекта задан значением 4 недели, изменяется по кнопке «Фильтров» в диапазоне от 1 до 7 недель. Межотраслевой стандарт Utilization Rate — 80%, отмечен на графике чёрной линией. Экспортировать в Excel можно только таблицу с плоской структурой. На вкладках «Выявление проблем» и «Сравнение эффективности процессов» рассматриваются только закрытые заявки; выбранный период — период создания заявок. Если рейтинг не используется, в отчёте будет прочерк. «Коэффициент полезной загрузки исполнителей» в «Общей аналитике» фильтруется только в разрезе исполнителей.

**⚠ Грабли.** «Отработано всего» и «Выполнено работ» расходятся при пересечении времени работ — это разные показатели, а не ошибка. Переработкой считается любой час из «Выполнения» вне графика работы, даже если других работ в этот день не вносилось. Без актуальных графиков работы в карточках сотрудников и заполненной вкладки «Выполнение» Utilization Rate, «Количество выполненных заявок на исполнителя», MTTR и переработки считаются некорректно. Чем больше число «HubEx Рейтинга», тем хуже: 1 — лучший. «Просрочено» в «Отчете для клиента» включает и активные, и выполненные заявки с истёкшим крайним сроком. Мини-диаграмма просроченных заявок в «Общей аналитике» — сама фильтр: щелчок по красному сектору фильтрует все диаграммы.
