# Замер полноты сжатого контекста

Стенд, которым 2026-08-27 сравнивали поразделную сборку и цельный проход. Он же —
способ проверять полноту файла после каждой квартальной пересборки.

## Состав

- `questions.md` — 40 вопросов без эталонов. Это то, что даётся отвечающему.
- `facts-A.md`, `facts-B.md` — те же вопросы с эталонными ответами и источниками.
  Составлены двумя агентами по страницам вики; ни один не видел сравниваемых файлов.
- `answers-sections.md` — ответы по поразделному файлу (`hubex-context.md` на 2026-08-27).
- `answers-whole.md` — ответы по цельному файлу.
- `variant-whole-2026-08-27.md` — сам цельный файл того прогона, эталон полноты.

Состав набора: 12 «параметр», 10 «моделирование», 10 «стопер», 8 «стык». Стыковые
вопросы требуют фактов с двух страниц из разных тем — именно их поразделная сборка
теряла чаще всего.

## Как прогонять

1. Дать агенту **только** проверяемый файл и `questions.md`. Явно запретить читать
   `pages/**`, эталоны и прочие варианты файла: иначе меряется эрудиция агента, а не
   полнота файла.
2. Потребовать по каждому вопросу статус ЕСТЬ / ЧАСТИЧНО / НЕТ и указание, чего не
   хватает при ЧАСТИЧНО.
3. Сверить с эталонами **руками**. Самооценка отвечающего систематически осторожнее
   реальности: в замере 2026-08-27 из семи «ЧАСТИЧНО» три были полными ответами.
4. Проверить транскрипт прогона на упоминания запрещённых путей.

Дешёвая дополнительная проверка: вытащить числа из эталона и из ответа и посмотреть,
какие числа эталона в ответе не встретились. Ловит потерю параметров в ответах,
которые выглядят уверенными.
